# Project の目標（決めて、週1で1歩進める）

目的: **本人が覚えていなくても、Project が目標に向かって進むこと。**
目標が無い Project では、まず目標を決める。決めるのは本人で、AI は材料と案を出す。

★**目標は Project のメモリに `goal.md` として1つだけ置く。**Project の中の Claude はどのスレッドでも
メモリを読むので、ここに置けば作業を選ぶたびに目に入る。repo には置かない
（1つの Project が複数の repo にまたがり、repo を持たない Project もある）。

## goal.md の形

```markdown
---
name: goal
description: この Project の目標と、いまの到達点。作業を選ぶ前に読む
metadata:
  type: project
---

- 目的: 「<本人の言葉そのまま>」（<どこで言ったか・日付>）／無ければ（空欄＝本人に聞く）
- いまの到達点: <1つ。終わったと判定できる条件>（目安 YYYY-MM-DD）
- 次の一手: <1つ。誰が（AI／本人）・大きさ>
- 合意: YYYY-MM-DD に本人が選んだ／未
- 歩み: <日付> <1行>（新しい順に5行まで。古い行は消す）
```

## 1. 読む

メモリの `goal.md` を読む。無い、または `合意: 未` なら 2 へ。合意済みなら 3 へ。

## 2. 決める（対話のときだけ）

⚠️ **無人の実行では決めない。**案を作って1枚のカードで聞き、そこで終わる。

- **材料を集める**: Project チャットの最近の流れ、メモリ、スレッドの一覧、Project の repo の
  README・CLAUDE.md・open issue。
- **目的は本人の言葉だけ。**どこかに本人が書いた・言った一文があれば、そのまま引用して出どころを書く。
  ★**見つからなければ AI が作文しない。**空欄にして、1行で聞く。
- **到達点は3案をカードで出す**（`ask_decision`）。各案は ①1か月ほどで届く ②届いたかを
  記録・数字・検査で判定できる ③本人が過去に言ったことに根ざす。おすすめを1つ付け、理由を1行。
  ★**出す前に、各案の現在値をいまの記録で測ってカードに書く。**古い数字や他人のまとめから案を作ると、
  選んだ時点でもう届いている到達点を出してしまう（実際に起きた）。
- 選ばれたら `goal.md` を書き、`合意:` に日付を入れる。次の一手も1つ決めて書く。
- 初回なら 4 で定期実行を置く。

## 3. 進める（1回に1歩）

1. **到達点に届いたか**を判定する。根拠（commit・`file:line`・数字・記録）を書けるときだけ「届いた」と言う。
   届いていたら、次の到達点を 2 と同じ形の3案でカードにして聞く。勝手に次へ進まない。
2. 届いていなければ、**次の一手を1つだけ進める。**
   - AI でできるなら、やる。repo を触るなら、その repo の規則（CLAUDE.md・CI・PR の扱い）を先に読んで従う。
     PR は下書きで出し、マージしない。
   - 本人の手が要るなら、**最初の1アクション**まで分解して1行で渡す（何を・どこで・何分）。
3. `歩み:` に1行足し、`次の一手:` を更新する。
4. 本人に聞くことは**1回に1つ**。カードで聞く。

### 間引き（催促にしない）

- 前回の問い・PR・渡した一手に**返事が無ければ、新しく作らない。**「前回の〜を待っている」と1行書いて終わる。
- 4週続けて返事が無ければ、頻度を落とすか止めるかを**1回だけ**カードで聞く。
- ⚠️ 返事が無いことを責める書き方をしない（残りの数や空いた週数を並べない）。

## 4. 週1の定期実行を置く（初回だけ）

`list_triggers` で `project-goal` という名前の定期実行が**この Project に**もう在るか見る。無ければ作る:

- `create_trigger`、`create_new_session_on_fire: true`、週1回（本人のタイムゾーンで朝。分は00/30を避ける）
- prompt: 「project-goal skill の手順 3（進める）を実行する。無人なので 2（決める）はしない」
- 作ったら、いつ走るかを本人に1行で言う。

⚠️ 定期実行は走るたびにこの Project の新しいスレッドになる。スレッドの中で完結させ、Project チャットへは書かない。
そのスレッドは Project の設定（repo・メモリ）で走り、カード（`ask_decision`）も出せる。作成時に渡した環境・通知は使われない。
定期実行の一覧を管理している repo があるなら、その repo の規則に従って作ったことを記録する。

## やらないこと

- 到達点や目的を、本人に断らずに書き換えない。
- 1回に2歩以上進めない。2つ以上聞かない。
- 取り消せない操作（本番への反映・削除・外への送信・マージ）をしない。
- `goal.md` 以外のメモリに目標を書かない（2か所にすると、片方だけ直されて食い違う）。
