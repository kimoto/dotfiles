# セッションの締め（残っているものを、消えない場所へ）

目的: **このセッションを閉じても何も失われない状態にする。**やりかけは、いま仕上げるか、
次のセッションが見つけられる場所に印を置くか、どちらか。
★読むだけの確認は断らずに実行する。**置き場所が決まらないものだけ聞く。**

## いつ走るか

締めの合図で走る。`/wrapup` と打たれなくても「残件は?」「閉じていい?」「もう終わり」も合図。

★**聞かれなくても自分から出す。ただし4つ全部そろった時だけ:**

1. このセッションで commit を1つ以上した（雑談・調べ物だけの回では出さない）
2. 直前のターンで成果を報告し終え、本人への問いを残していない
3. 本人の最後の発話が相槌（「おけ」「ありがとう」）で、新しい仕事を持ち込んでいない
4. このセッションでまだ締めていない（1セッション1回）

⚠️ **迷ったら出さない。** 出しそこねても本人が「残件は?」で取り返せるが、早すぎる締めは作業の途中に挟まるノイズになる。
⚠️ **重い儀式にしない。** 毎回の長いまとめは、本人が手で聞いていた頃より悪い。

★**repo に自前の締め skill があれば、そちらが入口。** その skill がこの手順を中で通し、その repo だけの項目を足して、返事を1回にまとめる。⚠️ 2本を続けて走らせない（同じ残件・git 状態が二度出る）。

## 1. 作業ツリーとブランチ

`git status` と `git log @{upstream}..` — 未コミット・未 push・このセッションで作ったブランチ。
仕上げられるものは仕上げる。⚠️ わざと途中で止めるものは、**黙って放置せず 3 で印を置く**。
⚠️ **壊れたまま閉じない。**build / test を走らせたセッションなら、最後の実行が通っているか。
通していないなら軽く走らせる。重くて走らせないなら★**「未確認」と名指しする**（黙ると通ったことになる）。

## 2. 出したままの PR・走らせたままのもの

このセッションで出した PR の CI と、返していないレビュー。CI・レビュー・デプロイ待ちは、
片付けるか、次が拾えるよう起票する。⚠️ **走らせたままの処理や監視は、止めるか回収する**。

## 3. 言ったのにやっていないこと・残件

「あとで」「次回」「やっておきます」「確認は後で」を会話から拾う。
⚠️★**全件。小さい・些細・言っただけ、で落とさない。**選別はここではなく、置き場所の側でやる
（issue にするか、メモリにするか）。**1件につき置き場所は1つ**:

- **その repo の話で、公開して問題ない** → その repo の issue。
  ⚠️ 公開 repo に**内部のホスト名・ユーザ名・私的な詳細を書かない**

  ⚠️ 新しい issue は1つの repo に、このセッションで立てた分と合わせて3件まで。超えるなら、残りをチェックリストにした1件を3件目にする
- **私的、または repo をまたぐ** → メモリ（1ファイル1件・`MEMORY.md` に索引・日付は絶対日付）
- **すでにどこかに在る** → その参照がまだ正しいか確かめ、ずれていたら直す

⚠️ **二重に持たない。**issue にしたなら、メモリはそれを指すだけにする。

★**その時期が来ないと判断できないものは、新しいセッションを予約して閉じる**（`rules/closing.md`）。予約の手段:

- **クラウド／web**: `create_trigger` に `run_once_at` と `create_new_session_on_fire`。
  拒否されたらコーディネーター宛ての `send_later` で新しいスレッドを立ててもらう
- **手元の CLI**: `/schedule`（クラウド側に作るので PC を閉じても発火する。一回きりの実行も作れる）

## 4. メモリの手入れ

このセッションで分かった**当たり前でないこと**を残す。⚠️ repo が既に持っているもの
（コード・commit・CLAUDE.md）は書かない。思い出したメモリが誤りだったら、その場で直すか消す。

⚠️★**同じ注意を別のセッションでも言われているなら、置き場所はメモリではなく
`~/.claude/rules/`。** メモリは思い出せたときだけ効き、rules は毎回読まれる。
★条件は「機械が変わっても成り立つか」— 成り立つなら rules、この repo だけなら `CLAUDE.md`、
この一件だけならメモリ。⚠️ **rules は全セッションが読む代金を払う**ので、数行で言えないものは
skill にする。

⚠️★**もう一つの関門は「誰が動くか」。** 人に向けた助言（何を任せるか、どこまで見るか）は、
全セッションが代金を払って誰も動かない。★読んだ自分が何を変えるか一文で言えないなら、
置き場所が違う(本人へ直接、または issue へ)。

## 5. 返し方

⚠️★**`session-resume` の順で返す。**集めたものをそのまま並べたリストは、
**何が問題だったかを覚えている人にしか読めない**。
⚠️★**拾った残件は全件出す**（並べ方で読ませる。数で切らない）。
最後に「このセッションにしか無いものは無い」と言い切るか、**在るなら何がなぜ残るか**を名指しする。
★**「閉じて大丈夫か」は判断ではなく検査。**触った全 repo で `git status --porcelain` が0行、`git status -sb` に `ahead` が無い——そろえば「閉じて大丈夫」と言い切る。欠けたら何が欠けたかを名指しする（「たぶん大丈夫」と濁さない）。閉じる操作は本人のもので、こちらが出すのは判定だけ。
