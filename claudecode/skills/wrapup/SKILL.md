# セッションの締め（残っているものを、消えない場所へ）

目的: **このセッションを閉じても何も失われない状態にする。**やりかけは、いま仕上げるか、
次のセッションが見つけられる場所に印を置くか、どちらか。
★読むだけの確認は断らずに実行する。**置き場所が決まらないものだけ聞く。**

## 1. 作業ツリーとブランチ

`git status` と `git log @{upstream}..` — 未コミット・未 push・このセッションで作ったブランチ。
仕上げられるものは仕上げる。⚠️ わざと途中で止めるものは、**黙って放置せず 3 で印を置く**。
⚠️ **壊れたまま閉じない。**build / test を走らせたセッションなら、最後の実行が通っているか。
通していないなら軽く走らせる。重くて走らせないなら★**「未確認」と名指しする**（黙ると通ったことになる）。

## 2. 出したままの PR・走らせたままのもの

このセッションで出した PR の CI と、返していないレビュー。CI・レビュー・デプロイ待ちは、
片付けるか、次が拾えるよう起票する。⚠️ **走らせたままの処理や監視は、止めるか回収する**。

## 3. 言ったのにやっていないこと・残件

「あとで」「次回」「やっておきます」「確認は後で」を会話から拾う。
⚠️★**全件。小さい・些細・言っただけ、で落とさない。**選別はここではなく、置き場所の側でやる
（issue にするか、メモリにするか）。**1件につき置き場所は1つ**:

- **その repo の話で、公開して問題ない** → その repo の issue。
  ⚠️ 公開 repo に**内部のホスト名・ユーザ名・私的な詳細を書かない**
- **私的、または repo をまたぐ** → メモリ（1ファイル1件・`MEMORY.md` に索引・日付は絶対日付）
- **すでにどこかに在る** → その参照がまだ正しいか確かめ、ずれていたら直す

⚠️ **二重に持たない。**issue にしたなら、メモリはそれを指すだけにする。

## 4. メモリの手入れ

このセッションで分かった**当たり前でないこと**を残す。⚠️ repo が既に持っているもの
（コード・commit・CLAUDE.md）は書かない。思い出したメモリが誤りだったら、その場で直すか消す。

## 5. 返し方

⚠️★**`session-resume` の順で返す。**集めたものをそのまま並べたリストは、
**何が問題だったかを覚えている人にしか読めない**。
⚠️★**拾った残件は全件出す**（並べ方で読ませる。数で切らない）。
最後に「このセッションにしか無いものは無い」と言い切るか、**在るなら何がなぜ残るか**を名指しする。
