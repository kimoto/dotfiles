# テストの穴を埋める

★**約束は「足したテストは、守っているものを壊すと赤になる」こと。**赤を見ていないテストは出さない。
1回の成果は「穴を1か所ふさぐテストの PR 最大1本」。手で呼んでも routine から呼んでも同じ手順。どの repo かは呼ぶ側が決める。
穴が尽きれば「候補なし」が続き、間隔が倍々に空く。それが飽和。

## 差分モード（PR を作った時の hook から）

範囲として差分（`<base>..HEAD`）を渡されたら、2 の探し方をその差分で変わった行にだけ使い、**見つけた穴を返すだけ**にする。テストは書かない・PR は作らない・backoff と open PR の数は見ない。直すのは呼んだ側。
⚠️ **0. 準備はしない。**ブランチを切り替えない・作業ツリーを動かさない（呼んだ側と同じツリーで並んで走る）。Scouts 節が無くても止まらない。わざと壊して試すときは自分用の worktree を作り、終わったら消す。
返し方は1行目 `🧪 穴 N件` か `🧪 穴なし（見た範囲）`、2行目から `ファイル:行 — 何を壊しても赤にならないか` を最大5件。

## 0. 準備

- 対象 repo の既定ブランチの最新で作業する（`git fetch origin <base> && git checkout -B <base> origin/<base>`）。
  `CLAUDE.md`（または `AGENTS.md`）を全部読む
- ★**repo ごとの決まりは `CLAUDE.md` の `## Scouts` 節にある。**そこに書かれたもの（検査コマンド・穴を探す道具・e2e の置き場所・触らない場所・却下済みの判断・PR の言語・open PR の上限）はこの skill より優先する
- ⚠️ `## Scouts` 節が無い repo では推測で進めない。何もせず「Scouts 節が無い」と報告して終わる
- ★**手を入れる前に、既定ブランチのまま `## Scouts` 節の検査を回す。**落ちたら:
  - 環境のせい（root で動いている・道具が無い）なら、落ちたものを控える。それに頼る穴は選ばない（壊さなくても赤なので、赤を見たことにならない）
  - 環境のせいでなければ（日付・外の版の変化）、直さずに「既定ブランチが赤（何が）」と報告して終わる
- GitHub 操作は GitHub MCP（`gh` は無いことがある）。search_* は使わず、list_pull_requests をラベルで絞る
- repo の visibility を確かめる。公開 repo なら、PR とコミットに private repo の名前・中身、ホスト名、どのマシンで使っているかを書かない

## 1. 無人で呼ばれたときの間隔（backoff）

呼ぶ側（routine）が間隔を決めているときは、最初の3項目を飛ばし、open PR の確認からにする。

- ラベル `routine:test-sweep` の PR（open/closed とも）の一番新しい created_at から今日（JST）までの日数 d。一件も無ければ routine を作った日を起点にする
- d が 0 か 2 の累乗（1・2・4・8・16…）のときだけ走る。PR が出れば翌日から間隔が戻り、出ない間は倍々に空く。それ以外は「休み（d 日PRなし）」の1行で終わる
- 照会に失敗したら休まずに走り、その旨を報告に書く
- open な `routine:test-sweep` PR があれば新しく作らず、その PR の CI と conflict だけ面倒を見て「前回の PR が未確認」で終わる
- `## Scouts` 節（とそこが指す文書）に open PR の上限があれば、そこに書かれた数え方で従う

## 2. 穴を探す（道具が見つけ、自分が判定する）

★**検出は道具に任せる。**毎回ちがう一行コマンドで探さない。`## Scouts` 節に書かれた道具を、書かれた通りに回す。道具の出力は候補であって根拠ではない。

- **壊して試す道具（mutation）**: 失敗の出口や条件をわざと壊し、テストが落ちなかった所（survivor）を出す。一番強い手がかり
  - ⚠️ 作業ツリーのファイルを書き換えながら走るものが多い。同じ checkout で別の作業をしない。終わったら `git status` で何も残っていないことを確かめる
- **カバレッジ**: 一度も通らない分岐・関数。通っていても確かめていない行は見えないので、mutation より弱い
- **どのテストにも選ばれないファイル**: テストの選び方が repo にあればその「無い」、無ければファイル名を `rg` でテスト側に探す
- **テスト無しで入った修正**: `git log` で直近の `fix` コミットのうち、テストを触っていないもの。同じ壊れ方が戻ってきても誰も気づかない
- **e2e の穴**: 人が触る入口（コマンド・キー・設定の読み込み・起動）で、部品の unit テストしか無いもの。部品が正しくても、つなぎ目が壊れれば人には壊れて見える。`## Scouts` 節が e2e の置き場所と helper を書いていればそれを使う

⚠️ `## Scouts` 節に道具が1つも無ければ、下の2つ（テスト無しの修正・どのテストにも選ばれないファイル）だけで探す。道具が要ると判断したら、その道具を足すこと自体を1本目の PR にする（その道具のテスト付き。一度わざと壊して red を見てから戻す）。

## 3. 1か所選ぶ

壊れても誰も気づかないと困る順:

1. 検査そのものの「違う」と言う出口（lint・check・golden 比較）。ここが黙ると、壊れた変更が素通りする
2. 安全の出口（秘密の検出、push・commit の前の止め、保護の確認、権限）
3. 人が毎日触る入口の e2e（起動しない・キーが効かない、を人より先に知る）
4. bootstrap や install の「ここまで来なかった」を知らせる出口
5. テスト無しで入った修正の再発
6. それ以外の入力エラー

選ばないもの:

- 道具が無い・OS が違う・`mktemp` 失敗のような、環境が壊れているときだけ通る出口。手間に見合わない
- 人だけが走らせると決まっているもの、install・削除など機械を変えるものを本物で走らせないと試せないもの（偽の HOME や fixture で閉じ込められるなら可）
- open な `routine:test-sweep` PR が触っているテスト、closed かつ未マージの `routine:test-sweep` PR で出した穴、`## Scouts` 節の「やらないと決めたもの」

## 4. テストを足す

- その穴を通る入力を作り、終了コードと、出るはずのメッセージ（e2e なら画面に出るもの）を確かめる。repo のテストの書き方（fixture・helper・一時ディレクトリの作り方）に合わせる
- ★**赤を見る。**守りたいものをわざと壊したまま新しいテストを回して落ちることを確かめ、元に戻して green を確かめる。mutation の survivor なら、その mutant が壊し方
- 本体を触るのは、テストから入れない所に入口を作るときだけ（例: 比較先のファイルを環境変数で差し替える）。既定の挙動は変えない。変えたならヘッダーのコメントに足す
- ⚠️ 既存のテストを skip・弱めない。テストが遅くなるなら、何秒増えたかを PR に書く
- テストが本物のバグを見つけたら、直さずに PR を止め、報告に書く（直すのはこの skill の約束の外）

## 5. PR

- ブランチ `test/<short-desc>`。Conventional Commits の `test(scope): …`（本体に入口を足しても、目的がテストなら `test`）
- コミット identity は `## Scouts` 節に書かれたもの（`-c user.name=… -c user.email=…` で渡す）。無ければ git の設定のまま
- push 前に `## Scouts` 節の検査を回す
- PR テンプレートがあれば埋める。Verification に、何を壊して赤になり、戻して緑になったかを書く
- ラベル `routine` と `routine:test-sweep`（付ける前に `"$(readlink -f ~/.claude/skills/test-sweep)/../../../bin/routine_labels.sh" routine:test-sweep` で色を揃えて無ければ作る。`gh` が無ければ飛ばす）、assignee は `## Scouts` 節に書かれた人（無ければ付けない）。subscribe_pr_activity して CI を緑にする。CI でそのテストが skip されずに走ったことをログで確かめる。**マージしない**

## 報告

1行目だけで分かる形にする（`<repo>` は repo 名）:

```
🧪 test-sweep <repo>: PR <URL>（どの穴・どの道具で・候補 N 件中）
🧪 test-sweep <repo>: 候補なし（見た範囲・使った道具）
⚠️ test-sweep <repo>: 確認できなかった（理由）
```

2行目以降に、選ばなかった候補のうち次に効きそうなものを3つまで。
⚠️「何も無かった」と「確認できなかった」を混ぜない。
