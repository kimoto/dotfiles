# 引き継ぎ（同じ作業を、空のコンテキストで続ける）

目的: **このセッションを読めない次のセッションが、プロンプト1つで同じ作業を続けられること。**
`wrapup` は「閉じても何も失われない」ための全件回収。こちらは**続けるのに要るものだけ**を運ぶ。
★自動 compact に任せない理由: 要約は**何を落としたかを言わない**。引き継ぎは自分で選んで書く。

## 1. 状態を会話の外に出す

★**会話にしか無い状態は `/clear` で消える。**ファイルと git に移してから書く。

- 作業ツリー: 途中でもブランチに commit する（WIP でよい。push はしなくてよい）。
  ⚠️ main の上なら先にブランチを切る
- 走らせたままの処理: 止めるか、次が拾えるように**何がどこに出力しているか**を書く
- ⚠️ 続ける作業と関係ない残件が会話の中にあれば、`wrapup` の 3 だけ先にやる（ここでは運ばない）

## 2. 引き継ぎに書くもの

- **目的** — 何を解こうとしているか、一文。★本人の言葉で頼まれた形を残す
- **どこにあるか** — repo・ブランチ・PR・issue・触っているファイル。⚠️ 中身は写さず指す
- ★**確かめ済みのこと**と、その根拠（コマンド・出力の要点・`file:line`）
- ★**捨てた案と理由** — 書かないと次のセッションが同じ道を最初から歩く
- **本人と決めたこと** — 「〜でいい」と言われた範囲。⚠️ 推測を決定として書かない
- **次の一手1つ**と、その時点で分からないこと

⛔ 書かないもの: 経緯の物語、diff やログの貼り付け（場所を指す）、次も読める CLAUDE.md・rules の再掲。

## 3. 書き方

⚠️★**「さっきの」「上記の」「例の」を使わない。**次のセッションには何も見えていない。
固有名詞とパスで書く。読んで質問が1つも湧かないかを、書いた後に一度読み直して確かめる。
★長くなるのは、運ぶべきでないものが混ざっている印。40行を超えたら 1 に戻って外に出す。

## 4. 返し方

コードブロック1つで渡し、その上に一行だけ: 「`/clear` して下を貼る」。
⚠️ **閉じるかは本人が決める。**渡した後に作業を続けるよう言われたら、そのまま続ける。
クラウド／Projects のスレッドでは `/clear` が無いので、新しいスレッドかセッションに貼るよう言う。
