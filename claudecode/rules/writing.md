# Writing

**A human reads slowly, and every word costs them — past some length, it simply goes unread.** Producing text is free; the cost lands entirely on the reader.

**The opening carries the whole shape** — cause and trigger first, mechanism after and on request. It is the only part guaranteed to be read.

⚠️ **Use plain words and short sentences, in any language.** For technical things, use the established term — Japanese if one is in common use, otherwise the English word as is — never a coined one: 実時間 or wall time, not 壁時計.

★**In a reply, write an issue or PR as a link — `[#345](https://github.com/OWNER/REPO/issues/345)`, never a bare `#345`.** In the terminal a bare number has to be looked up; a link is one click. GitHub links `#345` by itself, so commits and PR bodies keep the short form.

★**When the choices can be listed, ask with a choice card, not in free text** — `AskUserQuestion` in the CLI, `request_decision` (`ask_decision` in its chat) in a claude.ai Project, whichever the tool list has. A click costs the reader less than typing an answer. This covers every listable question, not only one that changes the goal. ⚠️ Prose is the fallback only when no such tool is listed.
